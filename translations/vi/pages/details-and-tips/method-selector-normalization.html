Chuẩn hóa các method selector

Go cho phép các dạng rút gọn của một số selector.

Ví dụ, trong chương trình sau, t1.M1 là dạng rút gọn của (*t1).M1, và t2.M2 là dạng rút gọn của (&t2).M2. Khi compile, compiler sẽ chuẩn hóa các dạng rút gọn thành các dạng đầy đủ ban đầu tương ứng.

Chương trình sau in ra 0 và 9, vì việc sửa đổi t1.X không ảnh hưởng đến kết quả đánh giá của *t1 trong quá trình đánh giá (*t1).M1.

package main

type T struct {
	X int
}

func (t T) M1() int {
	return t.X
}

func (t *T) M2() int {
	return t.X
}

func main() {
	var t1 = new(T)
	var f1 = t1.M1 // <=> (*t1).M1
	t1.X = 9
	println(f1()) // 0 
	
	var t2 T
	var f2 = t2.M2 // <=> (&t2).M2
	t2.X = 9
	println(f2()) // 9
}

Trong đoạn code sau, function foo chạy bình thường, nhưng function bar sẽ gây ra một panic. Lý do là s.M là dạng rút gọn của (*s.T).M. Khi compile, compiler sẽ chuẩn hóa dạng rút gọn thành dạng đầy đủ ban đầu của nó. Khi runtime, nếu s.T là nil, việc đánh giá *s.T sẽ gây ra một panic. Hai lần sửa đổi s.T không ảnh hưởng đến kết quả đánh giá của *s.T.

package main

type T struct {
	X int
}

func (t T) M() int {
	return t.X
}

type S struct {
	*T
}

func foo() {
	var s = S{T: new(T)}
	var f = s.M // <=> (*s.T).M
	s.T = nil
	f()
}

func bar() {
	var s S
	var f = s.M // panic
	s.T = new(T)
	f()
}

func main() {
	foo()
	bar()
}

Lưu ý rằng interface method value và method value lấy được qua reflection sẽ được mở rộng thành promoted method value với một độ trễ. Ví dụ, trong chương trình sau, việc sửa đổi s.T.X ảnh hưởng đến kết quả trả về của các method value lấy được qua reflection và qua interface.

package main

import "reflect"

type T struct {
	X int
}

func (t T) M() int {
	return t.X
}

type S struct {
	*T
}

func main() {
	var s = S{T: new(T)}
	var f = s.M // <=> (*s.T).M
	var g = reflect.ValueOf(&s).Elem().
		MethodByName("M").
		Interface().(func() int)
	var h = interface{M() int}(s).M
	s.T.X = 3
	println( f() ) // 0
	println( g() ) // 3
	println( h() ) // 3
}

Nguồn: https://github.com/golang/go/issues/47863

Lưu ý, official standard Go compiler có một bug trước version 1.20. Các compiler cũ de-virtualize một số interface method ở compile time, nhưng việc de-virtualize được thực hiện quá mức nên không đúng. Ví dụ, chương trình sau đáng lẽ phải in ra 2 2, nhưng sẽ in ra 1 2 nếu được compile bằng official standard Go compiler v1.19.

package main

type I interface{ M() }

type T struct{
	x int
}

func (t T) M() {
	println(t.x)
}

func main() {
	var t = &T{x: 1}
	var i I = t
	
	var f = i.M
	defer f() // 2 (đúng)

	// i.M được de-virtualize thành (*t).M tại compile time (bug).
	defer i.M() // 1 (sai)
	
	t.x = 2
}

Bug này đã được sửa trong Go toolchain 1.20.

Nguồn: https://github.com/golang/go/issues/52072
