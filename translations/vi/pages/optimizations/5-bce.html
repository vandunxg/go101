BCE (Loại bỏ kiểm tra giới hạn)

Go là một ngôn ngữ an toàn bộ nhớ. Khi indexing element của array/slice/string và thực hiện các thao tác subslice, Go runtime sẽ kiểm tra xem các index liên quan có nằm ngoài phạm vi hay không. Nếu một index nằm ngoài phạm vi, một panic sẽ được tạo ra để ngăn index không hợp lệ gây hại. Đây được gọi là kiểm tra giới hạn.

Các kiểm tra giới hạn giúp code của chúng ta chạy an toàn; mặt khác, chúng cũng khiến code của chúng ta chạy chậm hơn một chút. Đây là một đánh đổi mà một ngôn ngữ an toàn phải chấp nhận.

Kể từ Go toolchain v1.7, Go compiler tiêu chuẩn đã bắt đầu hỗ trợ BCE (loại bỏ kiểm tra giới hạn). BCE có thể tránh một số kiểm tra giới hạn không cần thiết, nhờ đó Go compiler tiêu chuẩn có thể tạo ra các chương trình hiệu quả hơn.

Phần sau liệt kê một số ví dụ để cho thấy BCE hoạt động trong những trường hợp nào và không hoạt động trong những trường hợp nào.

Chúng ta có thể dùng compiler option -d=ssa/check_bce để hiển thị những dòng code cần kiểm tra giới hạn.

Ví dụ 1

Một ví dụ đơn giản:

// example1.go
package main

func f1a(s []struct{}, index int) {
	_ = s[index] // line 5: Found IsInBounds
	_ = s[index]
	_ = s[index:]
	_ = s[:index+1]
}

func f1b(s []byte, index int) {
	s[index-1] = 'a' // line 12: Found IsInBounds
	_ = s[:index]
}

func f1c(a [5]int) {
	_ = a[0]
	_ = a[4]
}

func f1d(s []int) {
	if len(s) > 2 {
	    _, _, _ = s[0], s[1], s[2]
	}
}

func f1g(s []int) {
	middle := len(s) / 2
	_ = s[:middle]
	_ = s[middle:]
}

func main() {}

Hãy chạy nó với compiler option -d=ssa/check_bce:

$ go run -gcflags="-d=ssa/check_bce" example1.go
./example1.go:5:7: Found IsInBounds
./example1.go:12:3: Found IsInBounds

Output cho thấy chỉ có hai dòng code cần kiểm tra giới hạn trong đoạn code ví dụ trên.

Lưu ý rằng: các Go toolchain có version nhỏ hơn 1.21 không loại bỏ được các kiểm tra giới hạn trong function f1g.

Cũng lưu ý rằng, cho đến hiện tại (Go toolchain v1.24.n), official standard compiler không thực hiện BCE cho một operation trong generic function nếu operation đó liên quan đến type parameters và generic function không bao giờ được instantiate. Ví dụ, command go run -gcflags=-d=ssa/check_bce bar.go sẽ không report gì.

// bar.go
package bar

func foo[E any](s []E) {
	_ = s[0] // line 5
	_ = s[1] // line 6
	_ = s[2] // line 7
}

// var _ = foo[bool]

Tuy nhiên, nếu bật dòng khai báo variable, compiler sẽ report:

./bar.go:5:7: Found IsInBounds
./bar.go:6:7: Found IsInBounds
./bar.go:7:7: Found IsInBounds
./bar.go:4:6: Found IsInBounds

Ví dụ 2

Tất cả các kiểm tra giới hạn trong việc indexing element của slice và các thao tác subslice được hiển thị trong ví dụ sau đều được loại bỏ.

// example2.go
package main

func f2a(s []int) {
	for i := range s {
		_ = s[i]
		_ = s[i:len(s)]
		_ = s[:i+1]
	}
}

func f2b(s []int) {
	for i := 0; i < len(s); i++ {
		_ = s[i]
		_ = s[i:len(s)]
		_ = s[:i+1]
	}
}

func f2c(s []int) {
	for i := len(s) - 1; i >= 0; i-- {
		_ = s[i]
		_ = s[i:len(s)]
		_ = s[:i+1]
	}
}

func f2d(s []int) {
	for i := len(s); i > 0; {
		i--
		_ = s[i]
		_ = s[i:len(s)]
		_ = s[:i+1]
	}
}

func f2e(s []int) {
	for i := 0; i < len(s) - 1; i += 2 {
		_ = s[i]
		_ = s[i:len(s)]
		_ = s[:i+1]
	}
}

func main() {}

Hãy chạy nó, chúng ta sẽ thấy không có output. Đúng vậy, official standard Go compiler thông minh đến mức nhận ra rằng mọi kiểm tra giới hạn trong đoạn code ví dụ trên đều có thể được loại bỏ.

$ go run -gcflags="-d=ssa/check_bce" example2.go

Lưu ý: trước v1.24, official standard Go compiler không loại bỏ được các kiểm tra giới hạn trong hai loop sau.

func f2g(s []int) {
	for i := len(s) - 1; i >= 0; i-- {
		_ = s[:i+1]
	}
}

func f2h(s []int) {
	for i := 0; i <= len(s) - 1; i++ {
		_ = s[:i+1]
	}
}

Ví dụ 4

Kể từ Go toolchain v1.19, kiểm tra giới hạn trong function f5a đã được loại bỏ thành công,

func f5a(isa []int, isb []int) {
	if len(isa) > 0xFFF {
		for _, n := range isb {
			_ = isa[n & 0xFFF]
		}
	}
}

Tuy nhiên, trước Go toolchain v1.19, kiểm tra này không được loại bỏ. Các compiler trước version 1.19 cần một hint để loại bỏ kiểm tra, như được thể hiện trong function f5b:

func f5b(isa []int, isb []int) {
	if len(isa) > 0xFFF {
		// Một hint thành công (đối với compiler v1.18-)
		isa = isa[:0xFFF+1]
		for _, n := range isb {
			_ = isa[n & 0xFFF] // BCEed!
		}
	}
}

func f5c(isa []int, isb []int) {
	if len(isa) > 0xFFF {
		// Một hint không hoạt động (đối với compiler v1.18-)
		_ = isa[:0xFFF+1]
		for _, n := range isb {
			_ = isa[n & 0xFFF] // Found IsInBounds
		}
	}
}

func f5d(isa []int, isb []int) {
	if len(isa) > 0xFFF {
		// Một hint không hoạt động (đối với compiler v1.18-)
		_ = isa[0xFFF]
		for _, n := range isb {
			_ = isa[n & 0xFFF] // Found IsInBounds
		}
	}
}

Phần tiếp theo cho thấy thêm một số trường hợp cần compiler hint để tránh một số kiểm tra giới hạn không cần thiết.

Ví dụ 5

Trước Go toolchain v1.24, có một số kiểm tra giới hạn không cần thiết trong đoạn code sau:

func fz(s, x, y []byte) {
	n := copy(s, x)
	copy(s[n:], y) // Found IsSliceInBounds (1.24-)
	_ = x[n:]      // Found IsSliceInBounds (1.24-)
}

func fy(a, b []byte) {
    for i := range min(len(a), len(b)) {
        _ = a[i] // Found IsInBounds (1.24-)
        _ = b[i] // Found IsInBounds (1.24-)
    }
}

func fx(a [256]byte) {
	for i := 0; i < 128; i++ {
		_ = a[2*i] // Found IsInBounds (1.24-)
	}
}

func f4a(is []int, bs []byte) {
	if len(is) >= 256 {
		for _, n := range bs {
			_ = is[n] // Found IsInBounds (1.24-)
		}
	}
}

Kể từ version 1.24, tất cả các kiểm tra này đều được loại bỏ.

Trước version 1.24, chúng ta phải thêm một dòng hint để loại bỏ kiểm tra giới hạn trong function f4a:

func f4a(is []int, bs []byte) {
	if len(is) >= 256 {
		is = is[:256] // một hint thành công
		for _, n := range bs {
			_ = is[n] // BCEed!
		}
	}
}

Kể từ version 1.24, dòng hint này không còn cần thiết.

Đôi khi compiler cần một số hint để loại bỏ một số kiểm tra giới hạn

Official standard Go compiler vẫn chưa đủ thông minh để loại bỏ tất cả các kiểm tra giới hạn không cần thiết. Đôi khi, compiler cần được cung cấp một số hint để loại bỏ một số kiểm tra giới hạn.

Trong ví dụ sau, bằng cách thêm một block code if dư thừa vào function NumSameBytes_2, tất cả các kiểm tra giới hạn trong loop đều được loại bỏ.

type T = string

func NumSameBytes_1(x, y T) int {
	if len(x) > len(y) {
		x, y = y, x
	}
	for i := 0; i < len(x); i++ {
		if x[i] != 
			y[i] { // Found IsInBounds
			return i
		}
	}
	return len(x)
}

func NumSameBytes_2(x, y T) int {
	if len(x) > len(y) {
		x, y = y, x
	}
	
	// một hint thành công
	if len(x) > len(y) {
		panic("unreachable")
	}
	
	for i := 0; i < len(x); i++ {
		if x[i] != y[i] { // BCEed!
			return i
		}
	}
	return len(x)
}

Hint trên hoạt động khi T là một string type hoặc một slice type, trong khi mỗi hint trong hai hint sau chỉ hoạt động cho một trường hợp (theo Go toolchain v1.24.n).

func NumSameBytes_3(x, y T) int {
	if len(x) > len(y) {
		x, y = y, x
	}
	
	y = y[:len(x)] // một hint, chỉ hoạt động khi T là slice
	for i := 0; i < len(x); i++ {
		if x[i] != y[i] {
			return i
		}
	}
	return len(x)
}

func NumSameBytes_4(x, y T) int {
	if len(x) > len(y) {
		x, y = y, x
	}
	
	_ = y[:len(x)] // một hint, chỉ hoạt động khi T là string
	for i := 0; i < len(x); i++ {
		if x[i] != y[i] {
			return i
		}
	}
	return len(x)
}

Lưu ý rằng các version tương lai của official standard Go compiler sẽ trở nên thông minh hơn, nhờ đó các hint trên sau này sẽ không còn cần thiết.

Các slice ở cấp package thường không thân thiện với BCE, vì vậy chúng ta nên cố gắng assign chúng vào các slice local để loại bỏ một số kiểm tra giới hạn không cần thiết. Ví dụ, trong đoạn code sau, function fa0 thực hiện nhiều hơn các function fa1 và fa2 một kiểm tra giới hạn, do đó các lời gọi function fa1() và fa2(s) đều có performance tốt hơn fa0().

var s = make([]int, 5)

func fa0() {
	for i := range s {
		s[i] = i // Found IsInBounds
	}
}

func fa1() {
	s := s
	for i := range s {
		s[i] = i
	}
}

func fa2(x []int) {
	for i := range x {
		x[i] = i
	}
}

Official standard Go compiler hiện tại không loại bỏ được một số kiểm tra giới hạn không cần thiết

Tính đến Go toolchain v1.24.n, official standard Go compiler không loại bỏ các kiểm tra giới hạn không cần thiết sau đây.

func fd(data []int, check func(int) bool) []int {
	var k = 0
	for _, v := range data {
		if check(v) {
			data[k] = v // Found IsInBounds
			k++
		}
	}
	return data[:k] // Found IsSliceInBounds
}


// Đối với kiểm tra giới hạn duy nhất trong function sau,
// * nếu N == 1, nó sẽ luôn được loại bỏ.
// * nếu N là lũy thừa của 2, Go toolchain 1.19+ có thể loại bỏ nó.
// * với các trường hợp khác, Go toolchain không loại bỏ được nó.
func fe(s []byte) {
	const N = 3
	if len(s) >= N {
		r := len(s) % N
		_ = s[r] // Found IsInBounds
	}
}

func ff(s []byte) {
	for i := 0; i < len(s); i++ {
		_ = s[i/2] // Found IsInBounds
		_ = s[i/3] // Found IsInBounds
	}
}

func fg(src, dst []byte) {
	dst = dst[:len(src)]
	for len(src) >= 4 {
		dst[1] = // Found IsInBounds
			src[0]
		dst[0] = src[1]
		src = src[4:]
		dst = dst[4:] // Found IsSliceInBounds
	}
}
