Cái nhìn đầu tiên về generics tùy chỉnh

Trong thế giới generics tùy chỉnh, một type có thể được khai báo là generic type, và một function có thể được khai báo là generic function. Ngoài ra, generic type là defined type, nên chúng có thể có method.

Khai báo của một generic type, generic function hoặc method của một generic type chứa một phần type parameter list, đây là khác biệt chính so với khai báo của một type, function hoặc method thông thường.

Ví dụ về generic type

Trước tiên, hãy xem một ví dụ để thấy generic type trông như thế nào. Có thể đây không phải là một ví dụ hoàn hảo, nhưng nó cho thấy tính hữu ích của generic type tùy chỉnh.

package main

import "sync"

type Lockable[T any] struct {
	sync.Mutex
	Data T
}

func main() {
	var n Lockable[uint32]
	n.Lock()
	n.Data++
	n.Unlock()
	
	var f Lockable[float64]
	f.Lock()
	f.Data += 1.23
	f.Unlock()
	
	var b Lockable[bool]
	b.Lock()
	b.Data = !b.Data
	b.Unlock()
	
	var bs Lockable[[]byte]
	bs.Lock()
	bs.Data = append(bs.Data, "Go"...)
	bs.Unlock()
}

Trong ví dụ trên, Lockable là một generic type. So với các non-generic type, phần khai báo (nói chính xác hơn là specification) của một generic type có thêm một phần, đó là type parameter list. Ở đây, type parameter list của generic type Lockable là [T any].

Một type parameter list có thể chứa một hoặc nhiều khai báo type parameter, được đặt trong ngoặc vuông và phân tách bằng dấu phẩy. Mỗi khai báo type parameter gồm một tên type parameter và một type constraint. Trong ví dụ trên, T là tên type parameter và any là constraint của T.

Lưu ý rằng any là một predeclared identifier mới được giới thiệu trong Go 1.18. Nó là một alias của blank interface type interface{}. Ta hẳn đã biết rằng mọi type đều implement blank interface type.

(Lưu ý, nhìn chung, các cuốn sách Go 101 không nói type alias là một type. Chúng chỉ nói type alias biểu thị một type. Nhưng để thuận tiện, cuốn sách Go Generics 101 thường nói any là một type.)

Ta có thể xem constraint là type của các type parameter. Mọi type constraint thực ra đều là interface type. Constraint là phần cốt lõi của generics tùy chỉnh và sẽ được giải thích chi tiết trong chương tiếp theo.

T biểu thị một type parameter type. Scope của nó bắt đầu sau tên của generic type được khai báo và kết thúc ở cuối specification của generic type. Ở đây, nó được dùng làm type của field Data.

Kể từ Go 1.18, các value type được chia thành hai loại:

  1. type parameter type;
  2. ordinary type.

Trước Go 1.18, mọi value type đều là ordinary type.

Generic type là một defined type. Nó phải được instantiate để được dùng làm value type. Ký hiệu Lockable[uint32] được gọi là instantiated type (của generic type Lockable). Trong ký hiệu này, [uint32] được gọi là type argument list và uint32 được gọi là type argument, được truyền cho type parameter T tương ứng. Điều đó có nghĩa là type của field Data thuộc instantiated type Lockable[uint32] là uint32.

Một type argument phải implement constraint của type parameter tương ứng. Constraint any là constraint lỏng nhất; bất kỳ value type nào cũng có thể được truyền cho type parameter T. Các type argument khác được dùng trong ví dụ trên là: float64, bool và []byte.

Mọi instantiated type đều là named type và ordinary type. Ví dụ, Lockable[uint32] và Lockable[[]byte] đều là named type.

Ví dụ trên cho thấy generics tùy chỉnh tránh lặp code trong các khai báo type như thế nào. Nếu không có generics tùy chỉnh, cần khai báo nhiều struct type, như đoạn code sau đây cho thấy.

package main

import "sync"

type LockableUint32 struct {
	sync.Mutex
	Data uint32
}

type LockableFloat64 struct {
	sync.Mutex
	Data float64
}

type LockableBool struct {
	sync.Mutex
	Data bool
}

type LockableBytes struct {
	sync.Mutex
	Data []byte
}

func main() {
	var n LockableUint32
	n.Lock()
	n.Data++
	n.Unlock()
	
	var f LockableFloat64
	f.Lock()
	f.Data += 1.23
	f.Unlock()
	
	var b LockableBool
	b.Lock()
	b.Data = !b.Data
	b.Unlock()
	
	var bs LockableBytes
	bs.Lock()
	bs.Data = append(bs.Data, "Go"...)
	bs.Unlock()
}

Code non-generic chứa nhiều phần lặp lại, những phần này có thể được tránh bằng cách dùng generic type ở trên.

Ví dụ về method của một generic type

Một số người có thể không đánh giá cao implementation của generic type ở trên. Thay vào đó, họ thích dùng một implementation khác như đoạn code sau đây. So với implementation của Lockable trong section trước, implementation mới ẩn các struct field khỏi những người dùng generic type bên ngoài package.

package main

import "sync"

type Lockable[T any] struct {
	mu sync.Mutex
	data T
}

func (l *Lockable[T]) Do(f func(*T)) {
	l.mu.Lock()
	defer l.mu.Unlock()
	f(&l.data)
}

func main() {
	var n Lockable[uint32]
	n.Do(func(v *uint32) {
		*v++
	})
	
	var f Lockable[float64]
	f.Do(func(v *float64) {
		*v += 1.23
	})
	
	var b Lockable[bool]
	b.Do(func(v *bool) {
		*v = !*v
	})
	
	var bs Lockable[[]byte]
	bs.Do(func(v *[]byte) {
		*v = append(*v, "Go"...)
	})
}

Trong code trên, một method Do được khai báo cho generic base type Lockable. Ở đây, receiver type là một pointer type có base type là generic type Lockable. Khác với khai báo method cho ordinary base type, có một phần type parameter list nằm sau tên generic type Lockable của receiver trong phần receiver. Ở đây, type parameter list là [T].

Type parameter list trong khai báo method cho generic base type thực ra là sự lặp lại type parameter list được chỉ định trong specification của generic receiver base type. Để code gọn hơn, các type constraint được (và phải được) lược bỏ khỏi list. Đó là lý do type parameter list ở đây là [T], thay vì [T any].

Ở đây, T được dùng trong type của value parameter, func(*T).

  • Type của method Do thuộc instantiated type Lockable[uint32] là func(f func(*uint32)).
  • Type của method Do thuộc instantiated type Lockable[float64] là func(f func(*float64)).
  • Type của method Do thuộc instantiated type Lockable[bool] là func(f func(*bool)).
  • Type của method Do thuộc instantiated type Lockable[[]byte] là func(f func(*[]byte)).

Lưu ý rằng tên type parameter được dùng trong khai báo method cho generic base type không bắt buộc phải giống các tên tương ứng được dùng trong specification của generic type. Ví dụ, khai báo method ở trên tương đương với khai báo được viết lại sau đây.

func (l *Lockable[Foo]) Do(f func(*Foo)) {
	...
}

Tuy vậy, không giữ các tên type parameter tương ứng giống nhau là một cách làm không tốt.

Nhân tiện, tên của một type parameter thậm chí có thể là blank identifier _ nếu nó không được dùng (điều này cũng đúng với các type parameter trong khai báo generic type và function). Ví dụ,

func (l *Lockable[_]) DoNothing() {
}

Các generic type alias

Các generic type alias được hỗ trợ kể từ Go 1.24.

type TreeMap[K comparable, E any] struct {
	// ... các field không được export
}

// Một số generic type alias:
type TreeSet[K comparable] = TreeMap[K, struct{}]
type TreeMapWithIntKey[E any] = TreeMap[int, E]
type TreeMapWithStringKey[E any] = TreeMap[string, E]

Ví dụ về generic function

Bây giờ, hãy xem một ví dụ về cách khai báo và sử dụng các generic function (không phải method).

package main

// NoDiff kiểm tra xem một collection
// các value có hoàn toàn giống nhau hay không.
func NoDiff[V comparable](vs ...V) bool {
	if len(vs) == 0 {
		return true
	}
	
	v := vs[0]
	for _, x := range vs[1:] {
		if v != x {
			return false
		}
	}
	return true
}

func main() {
	var NoDiffString = NoDiff[string]
	println(NoDiff("Go", "Go", "Go")) // true
	println(NoDiffString("Go", "go")) // false
	
	println(NoDiff(123, 123, 123, 123)) // true
	println(NoDiff[int](123, 123, 789)) // false
	
	type A = [2]int
	println(NoDiff(A{}, A{}, A{}))     // true
	println(NoDiff(A{}, A{}, A{1, 2})) // false
	
	println(NoDiff(new(int)))           // true
	println(NoDiff(new(int), new(int))) // false

	println(NoDiff[bool]())   // true

	// _ = NoDiff() // error: cannot infer V
	
	// error: *** does not implement comparable
	// _ = NoDiff([]int{}, []int{})
	// _ = NoDiff(map[string]int{})
	// _ = NoDiff(any(1), any(1))
}

Trong ví dụ trên, NoDiff là một generic function. Khác với non-generic function và tương tự generic type, khai báo của generic function có thêm một phần, đó là type parameter list. Ở đây, type parameter list của generic function NoDiff là [V comparable], trong đó V là tên type parameter và comparable là constraint của V.

comparable là predeclared identifier mới được giới thiệu trong Go 1.18. Nó biểu thị một interface được implement bởi mọi comparable type. Nó sẽ được giải thích chi tiết hơn trong chương tiếp theo.

Ở đây, type parameter V được dùng làm type của variadic (value) parameter.

Các ký hiệu NoDiff[string], NoDiff[int] và NoDiff[bool] được gọi là instantiated function (của generic function NoDiff). Tương tự instantiated type, trong các ký hiệu này, [string], [int] và [bool] được gọi là type argument list. Trong các list này, string, int và bool được gọi là type argument, tất cả đều được truyền cho type parameter V.

Toàn bộ type argument list có thể được bỏ hoàn toàn khỏi một instantiated function expression nếu tất cả type argument có thể được suy ra từ các value argument. Đó là lý do một số lời gọi generic function NoDiff trong ví dụ trên không có type argument list.

  • Trong lời gọi NoDiff("Go", "Go", "Go"), type argument được suy ra là string, type mặc định của các value argument.
  • Trong lời gọi NoDiff(123, 123, 123, 123), type argument được suy ra là int, type mặc định của các value argument.
  • Trong hai lời gọi có A{} và A{1, 2} làm value argument, type argument được suy ra là [2]int, type của các value argument.
  • Trong hai lời gọi có new(int) làm value argument, type argument được suy ra là *int, type của các value argument.

Lưu ý rằng tất cả các type argument này đều implement interface comparable. Các type không comparable, chẳng hạn như []int và map[string]int, không được truyền làm type argument của các lời gọi đến generic function NoDiff. Ngoài ra, mặc dù any là một comparable (value) type, nó không implement comparable, nên cũng không phải là type argument hợp lệ. Nội dung này sẽ được nói chi tiết trong chương tiếp theo.

Ví dụ trên cho thấy generics tránh lặp code trong các khai báo function như thế nào. Nếu không có generics tùy chỉnh, ta cần khai báo một function cho mỗi type argument được dùng trong ví dụ. Phần thân của các khai báo function này gần như giống nhau.

Có thể xem generic function là dạng đơn giản hóa của method của generic type

Có thể xem generic function được trình bày trong section trên là dạng đơn giản hóa của method của một generic type, như trong đoạn code sau.

package main

type NoDiff[V comparable] struct{}

func (nd NoDiff[V]) Do(vs ...V) bool {
	... // giống phần thân của generic function ở trên
}

func main() {
	var NoDiffString = NoDiff[string]{}.Do
	println(NoDiffString("Go", "go")) // false
	
	println(NoDiff[int]{}.Do(123, 123, 789)) // false
	
	println(NoDiff[*int]{}.Do(new(int))) // true
}

Trong code trên, NoDiff[string]{}.Do, NoDiff[int]{}.Do và NoDiff[*int]{}.Do là ba method value của các instantiated type khác nhau.

Ta có thể xem generic type là một không gian type parameter, và xem tất cả method của nó là các function dùng chung không gian type parameter đó.

Để mô tả đơn giản, đôi khi trong cuốn sách này, method của generic type cũng được gọi là generic function.
